# 需求 PRD：Android 相册应用（REQ-ALBUM）

本文件是**需求级**文档，由产品在澄清后写出。据此决定开一个还是多个 feature；拆分结论见同目录 `split.yaml`。

## 背景与问题

用户需要一款从零打造的独立 Android 相册 App，在手机、平板与折叠屏上浏览与管理本机图片与视频。当前无既有产品可改造，需自建应用壳、媒体访问与核心浏览/管理体验。

核心痛点：

- 需要合规访问系统媒体库（含运行时权限与隐私披露）
- 需要按时间与图集高效浏览大量媒体
- 需要沉浸式大图体验（滑动、无极缩放）及基础管理（收藏、删除/回收站）

## 目标用户与成功标准

| 项 | 说明 |
| --- | --- |
| 目标用户 | 希望在本机浏览、整理照片与视频的 Android 手机 / 平板 / 折叠屏用户 |
| 平台 | Android 手机、平板、折叠屏（自适应布局；非三端各做一套独立 App） |
| 形态 | 从零独立 App（非插件、非系统相册替换强制方案） |

**成功标准（需求级）**

1. 用户完成权限授予后，能在时间线与图集中看到本机图片与视频。
2. 可进入大图：左右滑动切换、双指无极缩放；视频可预览/播放（至少可查看）。
3. 可收藏；可删除并进入回收站，可从回收站恢复或彻底删除。
4. 主路径操作流畅易用：列表滚动与大图切换无明显卡顿、无阻断式错误导致无法继续浏览（量化指标在各 feature `spec.yaml` 的 `A*` 中落地）。

## 范围

### 做（首期）

| 能力块 | 说明 |
| --- | --- |
| C1 权限与媒体接入 | 读取系统媒体库；处理运行时权限与隐私合规（含 Android 13+ 照片/视频相关权限策略） |
| C2 时间线浏览 | 按时间展示本机图片与视频缩略图网格/列表，可进入详情 |
| C3 图集分组 | 按系统图集/文件夹分组浏览 |
| C4 大图与手势 | 大图查看、左右滑动切换、无极缩放 |
| C5 视频查看 | 时间线/图集中展示视频；详情侧可预览或播放 |
| C6 收藏 | 标记/取消收藏；可查看收藏集合 |
| C7 删除与回收站 | 删除移入回收站；回收站内恢复或彻底删除 |

### 不做（首期明确排除）

- 云同步 / 云盘备份
- AI 识图、智能分类、人脸相册
- 视频编辑、图片编辑（裁剪滤镜等）
- 社交分享链路、多账号体系
- 搜索（首期不做）
- 对外分享面板深度集成（首期不做）
- 替换系统默认相册的强制引导
- 多用户 / 工作资料隔离的复杂策略（遵循系统默认即可）

## 主流程与能力块

### 主流程 P1：首次进入 → 浏览

1. 启动 App → 展示权限说明 / 请求媒体权限  
2. 用户授权 → 扫描/加载系统媒体库  
3. 进入时间线，滚动浏览缩略图  
4. 可切换到图集 Tab/页，按图集进入子列表  

### 主流程 P2：大图沉浸

1. 在时间线或图集点击某一项  
2. 进入大图；左右滑切换相邻项；双指无极缩放  
3. 视频项进入详情后可预览/播放  
4. 返回列表，位置与状态可预期（不丢当前浏览上下文）  

### 主流程 P3：收藏与删除

1. 在大图或列表对单项收藏 / 取消收藏  
2. 从收藏入口查看已收藏项  
3. 删除单项 → 进入回收站（非立即物理删除）  
4. 回收站：恢复回库，或彻底删除  

### 能力块与拆分候选边界

| 能力块 | 可独立交付？ | 说明 |
| --- | --- | --- |
| C1+C2+C3 | 是 | 「能授权、能按时间/图集看见媒体」——最小可用浏览 |
| C4+C5 | 是 | 依赖浏览列表可点入；合入后补齐沉浸查看 |
| C6+C7 | 是 | 依赖媒体项可标识；合入后补齐管理 |

## 验收总览

需求级验收意图（可执行 `A*` 落在各 feature `spec.yaml`）：

| ID | 意图 |
| --- | --- |
| R-A1 | 未授权时有明确引导；授权后时间线可见本机图片与视频缩略图 |
| R-A2 | 图集列表可进入，且图集内媒体与系统分组一致（允许缓存延迟有说明） |
| R-A3 | 大图支持滑动切换与无极缩放；视频可查看 |
| R-A4 | 收藏状态可切换且收藏集合可浏览 |
| R-A5 | 删除进回收站；可恢复；可彻底删除 |
| R-A6 | 手机 / 平板 / 折叠屏主路径可完成上述操作（布局自适应，无关键控件不可达） |

## 依赖与风险

| 类型 | 内容 |
| --- | --- |
| 依赖 | Android 系统 MediaStore；运行时权限与分区存储策略 |
| 风险 | 大图库滚动与大图解码导致卡顿或 OOM；需缓存与采样策略 |
| 风险 | 折叠屏/平板信息架构若只做手机布局缩放，易出现留白或触控热区问题 |
| 风险 | 权限被拒或「仅选部分照片」模式下的空态与降级需产品定义 |
| 合规 | 隐私政策入口、权限目的说明；不得越权访问非媒体数据 |

## 开放问题

闭合前不影响先按下方草案拆 feature；进入对应切片 PRD/spec 前尽量闭合。

1. **最低 Android 版本**（建议：API 26+ 或团队既有基线）？  
2. **回收站保留策略**（如 30 天自动清理，还是仅手动彻底删除）？  
3. **「仅选择部分照片」权限**：首期是否必须完整支持，还是引导用户改授「允许所有」？  
4. **视频播放**：App 内播放器 vs 调起系统播放器？  
5. **「流畅」量化**：列表 60fps 目标？大图切换超时上限？首期以主观+无崩溃为主是否可接受？  
6. **收藏数据**：存在 App 私有库即可，还是需与系统收藏互通？
